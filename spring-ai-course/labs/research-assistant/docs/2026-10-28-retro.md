# Sales-week readiness review (2026-10-28)

Attendees: Lena, Sam, Priya, Omar

## Status of the risks
- RISK-1, cache stampede: Lena added a random jitter of 0 to 60 seconds to the TTL.
  The load test no longer shows database spikes. **CLOSED.**
- RISK-2, price eviction: closed after the stale-price incident (see the incident report).
- RISK-3 (new): **Redis is a single node with no failover.** If it fails during the sales week,
  every request goes to PostgreSQL, and the load test shows PostgreSQL can only take about
  40% of the sales-week traffic. **Status: OPEN**, owner Sam.

## Decisions
- Move to **Redis Sentinel** (3 nodes, automatic failover) in Q1 2027. Too risky to change
  before the sales week.
- For the sales week: keep a hot standby Redis node that Sam can switch to by hand in about
  5 minutes, and rate-limit the catalog API at 3,000 requests per second if Redis is down.
- No new features in the checkout service until the end of the sales week (code freeze from 2026-11-20).

## Other notes
- The team agreed that the cache project met its goal: 210 ms p95 instead of 840 ms.
- Priya asked for a dashboard of cache hit rate per page. Not planned yet.
